## M9 剧本与存档编辑工作区

本里程碑独立于既有未完成任务，只有在用户明确指定任务编号后才执行对应实现。第一阶段仅处理剧本/存档中的列表条目；`GameScenarios.json` 单对象及其地图、全局变量等内容不在本里程碑范围内。

- [x] `M9-01` 建立带数据作用域的配置标识与注册目录。
  - 范围：定义 Common、剧本/存档作用域，使配置身份不再只依赖可能冲突的字符串 Key；保留现有 39 项 Common 注册结果和查找行为。
  - 验收：Common 注册表、元数据、专用编辑器和现有测试不回归；不同作用域允许使用相同局部 Key 且不会互相覆盖。
  - 依赖：无。
- [x] `M9-02` 注册剧本/存档的 22 个列表条目并实现档案类型探测。
  - 范围：根据游戏真实读写清单注册建筑、人物、势力、军势、军事、事件、宝物、年表等列表；用特征条目区分 Common 与剧本/存档并拒绝明显选错的文件。
  - 验收：注册项数量、条目名、记录类型和分类均有自动化测试；不注册 `GameScenarios.json`；剧本与存档共用同一套定义。
  - 依赖：`M9-01`。
- [x] `M9-03` 补强 `null`、缺失条目与空集合的数据语义。
  - 范围：区分缺失条目、顶层 `null`、空列表、属性 `null`、空字符串和空集合；属性面板提供显式“初始化”和“设为 null”操作，禁止静默规范化。
  - 验收：未编辑的 `null` 往返后保持不变；顶层异常状态有明确提示；列表中的空记录不会导致界面崩溃或被静默删除。
  - 依赖：`M9-01`。
- [x] `M9-04` 扩展通用档案仓储以安全加载和保存剧本/存档列表。
  - 范围：按作用域定义加载列表，保存时继续采用临时文件、备份、原子替换和内容指纹冲突保护；只替换修改过的列表条目。
  - 验收：使用代表性剧本夹具验证 22 个列表可读取；保存一个列表时其余列表和未管理的 `GameScenarios.json` 保持不变；保存结果可由游戏 `GameDataArchive` 重新读取。
  - 依赖：`M9-02`、`M9-03`。
- [x] `M9-05` 建立可同时承载 Common 与剧本/存档的编辑工作区模型。
  - 范围：工作区包含两个独立档案槽位，各自持有路径、文档、活动文档、未保存状态、内容指纹和生命周期；不把两个物理档案合并成一个 `EditorProject`。
  - 验收：两个档案可独立打开、替换和关闭；切换活动作用域不丢失各自的活动文档和编辑状态；领域及应用层测试覆盖状态切换。
  - 依赖：`M9-01`、`M9-04`。
- [x] `M9-06` 实现 Common 与剧本/存档顶层 Tab 及分类导航。
  - 范围：主界面提供两个大类 Tab；每个 Tab 按 `Category` 分组展示内部数据表、记录数和未保存标记，选择数据表后复用现有通用编辑区和属性面板。
  - 验收：切换 Tab 时分类、文档、标题和编辑内容同步切换；Common 不再平铺全部配置；未打开的槽位显示对应打开入口。
  - 依赖：`M9-05`。
- [x] `M9-07` 将打开、保存、另存为、关闭和外部变更监视路由到当前档案槽位。
  - 范围：分别提供打开 Common、打开剧本/存档及关闭当前档案；保存当前配置、保存当前档案、另存为和保存副本只操作正确的物理文件；保存全部可处理两个槽位。
  - 验收：任一槽位的操作不会写入另一档案；两个槽位分别检测外部修改；保存全部的部分失败能准确指出失败档案且不错误清除未保存状态。
  - 依赖：`M9-05`、`M9-06`。
- [x] `M9-08` 完善双档案的未保存确认、最近记录和界面状态恢复。
  - 范围：切换或关闭单个槽位只询问该槽位；退出时汇总两个槽位；最近记录保存档案作用域；分别记忆分类、文档、搜索条件和列宽。
  - 验收：取消关闭不会丢失任何槽位；同一路径按正确作用域恢复；重启后两个 Tab 的独立 UI 状态可恢复。
  - 依赖：`M9-07`。
- [x] `M9-09` 将搜索、JSON 导入导出和批量档案导入限定到当前作用域。
  - 范围：默认只搜索和传输当前 Tab 的文档；无 `Id` 的位置类列表仅允许适用的整表策略；操作日志标明 Common 或剧本/存档来源。
  - 验收：剧本操作不会匹配或修改 Common 同名数据；错误作用域的档案批量导入会在应用前阻止；现有 Common 导入导出行为不回归。
  - 依赖：`M9-05`、`M9-07`。
- [x] `M9-10` 作用域化校验、引用索引、删除影响检查和引用跳转。
  - 范围：引用目标使用“作用域 + 配置 Key”定位；先恢复现有 Common 校验，再声明剧本内部及剧本到 Common 的明确引用；校验结果可定位到正确 Tab、配置和记录。
  - 验收：Common 与剧本的同名/同 ID 记录不会串联；跨作用域有效引用可选择和跳转；缺失目标、重复目标及删除影响均指向正确档案。
  - 依赖：`M9-05`、`M9-09`。
- [ ] `M9-11` 使用真实规模样例完成端到端兼容验证并更新文档。
  - 范围：以 `190FDLM.dat` 的结构和数据规模验证加载、切换、编辑副本、保存、重开、`null` 保真及未管理条目保留；补充架构和使用说明，但不把真实游戏档案提交进仓库。
  - 验收：自动化夹具覆盖关键往返规则；在样例副本上人工验证 22 个列表及主要记录数；完整构建和测试通过；文档明确第一阶段边界与后续 `GameScenarios.json` 扩展点。
  - 依赖：`M9-06`—`M9-10`。
